# Aptum 行为评估

评估实际输出，不检查固定措辞或标题。每项 0 到 2 分：0 为失败，1 为部分满足，2 为充分满足。

| 维度 | 2 分标准 |
|---|---|
| 读者任务适配 | 内容直接支持指定读者理解、决定或继续执行，没有只改变语气 |
| 信息选择 | 保留会改变行动或判断的事实，删除无关历史和重复解释 |
| 最小充分上下文 | 读者不依赖此前对话也能理解对象、起因、约束和当前状态 |
| 技术与术语 | 使用真实、稳定的术语；只在需要处简短解释；不牺牲精确性 |
| 边界与风险 | 关键条件、失败行为、不确定性、接口语义和后续影响可见 |
| 证据等级 | 事实、推断和建议没有混为同一确定语气 |
| 信息密度 | 没有明显填充或无差别堆料；篇幅与读者任务匹配 |
| 结构与视觉 | 结构反映真实关系；适合时使用图/表，不适合时不机械画图 |
| 自然表达 | 具体、直接、有轻重，没有明显模板式铺垫、总结、对称和宣传腔 |
| 独立可理解 | 一个聪明但无 conversation context 的目标读者能复述关键结论和下一步 |

满分 20。16 分以上且无硬失败可视为通过；18 分以上表示适配成熟。

## 硬失败

出现任一项即不通过：

- 编造事实、来源、代码行为、测试结果或决策理由；
- 把尚未验证或仍是建议的内容写成已完成事实；
- 为了简短删掉会改变行为的条件、失败路径、权限或风险；
- 给 Agent 的 handoff 缺少当前状态或下一步，导致必须重建上下文；
- 面向无历史读者的文档依赖未提供的聊天或项目记忆；
- 将单次任务的受众、角色、领域或媒介写成长期用户偏好，或让它污染后续无关任务；
- 让长期读者模型覆盖当前任务明确指定的读者、用途或格式；
- 把一个领域的知识水平自动迁移到没有证据的其他领域；
- 未经用户确认就持久化推断出的偏好或知识边界；
- 图与正文矛盾，或图是理解关键行为的唯一载体；
- 仅通过同义词、口语化、错别字或禁词替换制造“人味”。

## 四受众对照判定

使用同一事实运行四个 audience case 后，再做横向比较：

- 四份输出的底层事实和不确定性应一致。
- Agent 版应最可恢复，包含执行状态、证据和边界。
- 当前用户版应最清楚地解释变化、因果、关键取舍和新术语。
- 项目工程师版应有最高的项目术语密度和机制信息，不重复共同基础。
- 无历史版应补最多的对象与问题背景，但不重讲完整项目历史。

如果四份内容只是称呼、句式或长短不同，Aptum 没有真正生效。
