# 去 AI 味模式：验证与更新

分开验证三件事：带进来的是否是完整上游、该不该启用、改写有没有改变意思。没有问题的句子保持原样也可以通过；不要用字数下降或自评分代替验证。

## 材料

- [上游 18 个短例](upstream/fixtures/cases.json)、[Markdown 文件样例](upstream/fixtures/structure.md)、[结构检查脚本](upstream/check_structure.py)及[原测试说明](upstream/README.md)均原样复制，来源与许可见[固定清单](../../references/humanizer-zh-source.json)。原测试说明中的路径属于上游仓库，在本仓库按下面的命令运行。
- [15 个集成用例](cases.yaml)检查明确触发、普通润色不触发、引用与否定、审阅不写回、范围延续与停用、作者样本、必要解释和文件保护。均为构造数据，不来自用户私人项目。
- [核对样例](smoke-examples.md)展示本次实现者的实际改写与逐项检查，不是独立盲测成绩。

## 确定性检查

在仓库根目录运行，不联网，也不修改输入：

```bash
python3 evals/humanizer-zh/check_bundle.py
python3 evals/humanizer-zh/upstream/check_structure.py \
  evals/humanizer-zh/upstream/fixtures/structure.md /path/to/edited-copy.md
```

第一条核对所有随包副本的 SHA-256、31 类检查点与 18 个唯一上游用例。校验值来自固定提交，验证通过表示副本完整，不表示上游没有问题。

第二条比较 YAML、代码、标题、链接目标、表格、步骤和显式 ID。它使用有限的 Markdown 匹配，不是完整解析器；不能覆盖所有 Markdown 写法或证明正文语义未变。对用户另行授权重排、改标题的任务，不能直接用严格相等判错。

## 行为评估

使用隔离安装和临时用户目录，不暴露真实读者档案、凭据或聊天。运行单个任务时，只交给被测 Agent 原始材料和请求，不能交给它 `expected_mode`、检查要点或示范答案。记录实际读取与写入：声称用了模块不等于真的完整读取；只审阅时文件必须无变化。

对上游短例测试 Aptum 整合时，在原请求前加“用 Aptum 去 AI 味”，其余要求与原文不变。上游普通“润色”请求若不加明确意图，应另归不触发测试，不能拿它判完整模块漏读。

逐项核对事实、归因、范围、时间、否定和完成状态；再检查读者是否少了理解障碍、作者声音与文体是否保留。编造、越权写入、丢掉关键条件或把临时模式持久化，均直接失败。允许判定没有实质差异；独立比较与采样要求沿用[主评估规则](../rubric.md)。
