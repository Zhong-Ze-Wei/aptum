# 本地读者档案

记录能稳定改善理解的信息：怎样把信息交给这个人，以及哪些知识可以接上。只提供可修正的背景，不建立人格、能力等级或完整生活画像。

## 读取与范围

默认位置是 `~/.config/aptum/reader-profile.md`。主要读者为当前用户时，本次上下文首次使用 Aptum 就读取存在的主档；已有有效内容则复用，明确修改、恢复后内容不明或写入前再读。没有文件或无法访问时继续任务，不创建空画像、不要求初始化，也不宣称跨会话已经记住。

当前明确要求、适用的项目约定和当前直接反馈优先于旧记录。知识不能跨领域外推；过往解释过、一次追问或一次使用术语，都不能证明长期掌握或不懂。

写给他人时以实际读者为准。替本人代笔可以使用其写作声音，但日报等规则只在相应场景适用。主档可列场景文件及适用条件；代笔时只读这个索引和匹配的 `contexts/*.md`，不把本人的知识当成读者知识。不匹配的场景内容不加载。

## 条目内容

保留稳定的理解偏好、有领域范围的知识依据、需要抵消的表达惯性。每条说明**适用范围、表达行为、依据与确认时间**；写成一两句可执行的提示，不用“技术中等”“喜欢简单内容”等笼统标签。

例如：“[机制解释] 先说明对象的实际作用和因果，再引入必要术语。来源：本人明确要求；确认：日期。”这是格式说明，不是新用户的默认偏好。推断没有得到确认时，只在当前会话中作为假设，不写进已确认记录；没有原始依据的旧记录标明来源待核对，不编造确认日期。

不保存人格推测、敏感个人信息、同事信息、一次性受众、临时角色、项目当前状态或无关经历。素材路径、查历史和保存同步等操作属于对应项目工作流；档案不是执行这些动作的授权。

## 识别与记录

当场识别可以自动，长期记录有明确门槛：

- “以后这样”“记住这个偏好”：保存清楚、稳定、范围明确的规则，简短告知改了什么。
- 请求根据交流建立档案：先给草稿，明确事实与推断，确认后保存；不为建档全量扫描聊天。
- 临时要求、转述别人偏好和行为推断：仅用于当前任务。反复造成明显返工时可顺手确认一次，不以出现次数自动晋升。
- 用户可一次性授权“保存我明确表达、范围清楚的长期偏好，保存后告知”。把这项选择写入主档的记录策略；它只免去重复确认，不授权保存推断或临时场景。没有这项授权时，仍仅按明确的长期记录请求写入。

新反馈当场生效，不必等待写入。需要长期更新时替换对应旧条目，不保留两条冲突的有效规则，不从“这个已懂”外推整个领域。只有明确的当前反馈可以纠正旧知识依据；档案存在较久不增加它的权威。

## 维护与控制

支持自然语言查看、改一条、删一条、暂停记录和本次不用。暂停记录仍可使用已有档案；本次不用则不读取或应用条目；两者都不等于删除。删除后不从历史或备份自行恢复，只承诺删除 Aptum 管理的活动记录，不声称清除了宿主记忆或原始聊天。

主档通常十条左右即可。重叠条目合并，场景内容按需移出；不维护候选库、置信度、计数器或变更日记，不因容量静默截断条件，也不因久未使用就删除仍有效的偏好。

写入前重读最新版，只修改目标条目；出现意外变化时停止覆盖并核对。多个 Agent 并行自动写入同一文件需要宿主提供锁或受控写入工具；普通 Markdown 约定不保证并发安全，没有保护时不要并行自动维护。

## 私有存储与可移植性

```text
~/.config/aptum/
├── reader-profile.md       通用条目、记录策略、可选场景索引
└── contexts/               有稳定场景才创建
    └── daily-writing.md    仅匹配的代笔任务读取
```

个人文件不进入 Skill 仓库、公共 reference、示例或发布包。隐藏目录不是保密措施；内容一旦加载就会由宿主及其模型处理，因此只保存必要信息。宿主已提供的确认偏好可用，但不自动复制内部记忆文件；来源冲突时服从当前明确确认，必要时询问。

这是一套文件读取与更新约定，不是后台记忆程序，不自动注册 hook 或跨设备同步。同机 Claude Code 与 Codex 只有都可访问此目录并遵循约定时才能共享。第一版无需钩子；若实际发现漏读，再由用户选择宿主适配，不能为此默认全程加载私人档案。
