# 读者判断：从身份到下游动作

身份不是最终判断，接收方在当前任务中的 downstream action 才是。本文件提供判断顺序和弱先验，不提供"某类人通常怎样写"的模板。

## 判断优先顺序

按以下顺序确定信息选择，高层证据始终压过下层：

1. **用户明确说明的接收方**——点名"给法务/给我父亲/给下一个会话的 AI"时，以真实接收者为准，任何先验让位；
2. **当前任务和交付媒介能可靠推断的接收方**——从请求、文件类型、项目位置和对话推断；推断结果影响结论时写明假设；
3. **接收方下一步需要完成的动作**——理解什么、判断什么、决定什么、执行什么；这是信息选择的直接依据；
4. **已有会话与项目上下文中的知识边界**——接收方已知什么、不知道什么、可能误解什么；
5. **身份类型**——只作弱先验，且必须让位于上面四层的任何具体证据。

未指定接收者时，默认主要读者是当前用户本人，按当前对话判断其知识背景，不默认初学者或专家。一个领域表现出的熟练程度不能自动迁移到另一个领域。

## 弱先验怎么用

身份先验（管理者、工程师、测试、运营、外部用户、Agent）只在缺少具体证据时提供初始假设，并且要预期它经常失准：

- "管理者不懂技术"可能为真，也可能这位管理者正是该模块的作者；与其降智，不如判断**他此刻要拍什么板**；
- "工程师懂术语"通常为真，但跨团队缩写、历史事故和非显然约束仍可能超出其范围；
- "Agent 能自己查" increasingly 为真，但状态、授权边界和停止条件它查不到，只能由交接内容给出。

先验给出假设后，回到下游动作验证：这条信息会改变他接下来做的事吗？不会就删，会就保留并置于他能看到的位置。

## 当前用户本人

按当前对话、用户明确表达的背景和可用的稳定偏好判断知识边界。优先说明：现状与已确认的事实、与此前相比的变化、原因、真正改变决策的约束、收益代价边界、容易被误解的地方。新术语首次出现时解释其在当前问题中的作用，不展开通识课程。

长期读者模型（如环境提供）只是先验，见 [personalization.md](personalization.md)；公共方法只描述如何使用该模型，具体 profile 存放在用户本地，不随 Skill 发布。

## AI Agent

Agent 的主要风险不是"看不懂术语"，而是缺状态后重新猜测、重复劳动或越过边界。面向 Agent 时判断它接下来要执行什么，并保证：目标与完成定义、当前状态（已完成/未完成/未验证）、相关文件与证据位置、已做决策及理由、不变量与授权边界、已尝试路径、下一步与停止条件、推断与事实的区别。

上下文完整不等于倾倒日志。不得把凭据、个人数据或无必要的大段敏感输出塞入 handoff。

## 没有历史上下文的人

把读者看作聪明的新加入者。优先补作者最容易忽略的四种上下文：对象（这个系统负责什么）、起因（问题为何存在）、约束（哪些条件不能改、为什么）、位置（本结论处于哪一阶段）。补到足以解释当前判断即可，不按时间线复述项目沿革。

内部代号首次出现时与职责放在一起，如 `Atlas`（负责发票对账的内部服务）。

## 混合受众

正文先服务主要任务，再用一句局部定义、局部注释、表格或链接为其他读者提供入口，不把全文降到最低共同知识水平。
