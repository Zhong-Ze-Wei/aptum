# 可选：结构化视觉表达

**本文件按需加载**：用户明确需要视觉化，或图表能显著降低**当前读者**理解关系、流程、状态或比较的成本时。不因为流程存在就画图，不因为内容复杂就默认 Mermaid——图形判断默认由模型自行完成，本文件只在校准困难时提供标准。

## 画图前先问

- 读者是否需要同时追踪三项以上实体之间的关系，或必须理解顺序、分支、状态、边界、前后变化？
- 当前媒介能否稳定渲染？
- 图是否比紧凑文字、表格更少歧义？

一项映射、一个简单步骤、一段短因果链不需要图。图如果只是把同一组 bullet 放进方框，删掉。

## 最小合适形式

| 关系 | 首选形式 |
|---|---|
| 精确字段、方案或前后映射 | 表格 |
| 组件、依赖、数据流、边界 | Mermaid flowchart |
| 跨角色调用和时间顺序 | Mermaid sequence diagram |
| 生命周期与允许迁移 | Mermaid state diagram |
| 简单层级或文件结构 | tree / ASCII |
| 界面不可靠渲染图 | 紧凑文字、表格或 ASCII |

## 图与正文分工

- 图必须由正文承载结论、不变量、失败行为和刻意省略的内容——关键事实不能只存在于颜色、位置或图形中；
- 节点使用真实、稳定、简短的名称，与正文一致；
- 生成后检查 Mermaid 语法与目标渲染器支持。

若内容只是"首次发送和三次重试均失败后进入 DLQ"，一句话比状态图更好。
