# 修复参考：自然、准确的技术表达

**本文件默认不加载。** 只在以下情况使用：用户明确要求润色或自然化；输出已经出现明显的模板化重复；表达风格本身已经阻碍理解；用户确认的长期偏好要求某种表达习惯。

它是生成后的修复参考，不是生成前的禁用清单——正常写作前不要想着"我不能这样写"。

## 先诊断信息问题

目标不是让文本"检测不出 AI"，而是让每句话有明确工作。AI 模板感常来自模型在不知道什么最重要时，用结构、强调和惯用短语代替判断。下表的症状是**失败信号**，不是逐词禁令；被动语态、破折号、类比、三项列表、技术术语只要承担真实功能，都可以出现。

| 症状 | 常见原因 | 更有效的处理 |
|---|---|---|
| 开头长时间不说结论 | 没决定读者为何而来 | 直接给当前状态、结论或问题 |
| 每节结尾重复总结 | 不信任读者或套模板 | 已产生信息闭环就停止 |
| 标题和 bullet 过多 | 用格式代替关系 | 合并连续因果；只保留可扫描边界 |
| 连续"三点式" | 追求完整感而非真实分类 | 按事实数量写，两项或五项都可以 |
| "核心是 / 本质是 / 真正重要的是"反复出现 | 依靠强调制造层级 | 用位置、证据和后果体现重要性 |
| "不是 X，而是 Y"连续使用 | 用反转制造洞见感 | 直接陈述 Y；只有纠正常见误解时保留 X |
| 宣传或咨询报告腔 | 缺少可验证事实 | 换成具体行为、数字、限制或证据 |
| 模糊归因 | 没有来源却想增加权威感 | 指明来源、标为推断，或删除 |
| 同义词轮换 | 把重复误认为文风问题 | 对同一组件坚持同一名称 |
| 句子节奏完全一致 | 机械套用句型 | 让句长跟承载的信息关系变化 |
| 术语密集但没有解释 | 把专业感当成准确性 | 保留必要术语，第一次出现时解释作用 |
| 为了"说人话"删掉条件 | 把短等同于清楚 | 恢复会改变行为或决策的边界 |

## 中文技术写作的额外摩擦

- 名词串太长时补出谁做什么："异步任务失败状态处理机制" → "Worker 如何记录异步任务的最终失败状态"；
- 少用从英文直译的抽象动词和名词化。能写"Worker 重试任务"，不写"任务重试能力由 Worker 进行承载"；
- 不用"赋能、抓手、闭环、沉淀、拉通"代替具体动作，除非组织内已有明确定义；
- 同一段不连续用"首先其次最后""值得注意的是""综上所述"主持文章；
- `DLQ`、idempotency、backpressure 等团队稳定使用的英文名称保留，解释其在当前系统的作用，不编造生硬中文替代。

## 类比的边界

类比适合帮第一次接触概念的读者建立粗略 mental model，一句建立直觉后立即回到真实行为。如果类比开始对应真实系统的多个组件、产生错误边界或持续数段，它已成为第二套需要学习的模型，删除。

## 修改示例

模板感较强：

> 值得注意的是，这一优化不仅显著提升了系统的健壮性，而且为未来可扩展架构奠定了坚实基础。总的来说，这是一项至关重要的改进。

有信息的版本：

> Worker 现在把四次发送均失败的任务移入 DLQ，避免同一任务阻塞主队列。代价是失败任务不会再自动恢复，运维需要通过重放工具处理。

问题不在某个禁词，而在原文没有说明改了什么、解决什么、付出什么。

过度简化：

> 失败任务会被单独保存。

适合当前用户：

> 首次发送和三次重试均失败后，任务会进入 DLQ（死信队列，保存最终处理失败任务的地方）。进入后不会自动重试，需要人工或补偿任务重新投递。

第二版更长，但保留了阈值、真实术语和后续影响，理解成本反而更低。
