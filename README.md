# Aptum

**适其人，适其事，适其言。**

Version: `0.1.0`

AI 已经很会写了：语法通顺、结构清楚、术语也基本用对。但在真实工作的信息传递里，它仍会犯四类错：

- **漏掉接收方真正需要的信息**——测试同学要的是"怎么重置状态，别每轮干等 15 分钟"，得到的却是一段 Redis 入门；
- **把最关键的事埋住**——唯一的阻塞项混在十条完成项里，breaking change 排在功能列表末尾；
- **为了显得完整，补出没确认的细节**——素材里没有的接口字段、命令、日期，写得像验证过一样；
- **交接时丢状态**——接手的人或下一次 AI 会话不知道哪些已验证、哪些不能动、何时该停，只好重新猜。

Aptum 解决这四类问题。它不是教 AI 怎么写——这已经不需要教——而是在 AI 写完之后、交出去之前，做一次安静的检查：接收方拿到的东西，够不够他完成下一步？最不能漏的事显眼吗？有没有把猜测写成事实？接手的人能安全继续吗？都没有问题，就不动。

## 它不解决什么

- 不是文档模板库——不教 README 或 ADR 长什么样；
- 不是"去 AI 味"工具——不追求像人写的，不用口语化或错别字伪装；
- 不是每次都要改——原答案已经合适时，它的正确动作是不动它；
- 不替代事实核查，也不替代你的领域判断。

## 什么时候值得用

存在真实的"信息换手"时：写给另一个角色或另一个团队、交给下一位工程师或下一次 AI 会话、做可能丢关键事实或边界的总结、用户点名要为某类读者改写。随手问答没有这个问题时，它不介入。

## 为什么推荐 GLM 5.3 及以上

Aptum 的规则层刻意做得很薄，只保留强模型自己也拿不稳的几件事：接收方还缺什么、什么最不能漏、什么是猜的、接手的人需要什么。写作本身完全交还给模型。它不为迁就弱模型增加规则——更弱的模型上不保证效果。

## 安装

把这句话交给支持 Skills 的 Claude Code 或 Codex：

```text
请替我安装这个 Skill：
https://github.com/Zhong-Ze-Wei/aptum
```

或手动安装：

```bash
# Claude Code
git clone https://github.com/Zhong-Ze-Wei/aptum.git ~/.claude/skills/aptum

# Codex
git clone https://github.com/Zhong-Ze-Wei/aptum.git ~/.codex/skills/aptum
```

安装后重新开始会话，让 Agent 重新发现 Skills。

## 使用

平时不用特意做什么——出现上面说的"信息换手"时它会自己出手。需要显式点名时，直接说：

```text
用 Aptum 把当前工作写成新 Agent 能安全接手、但不能自行部署的交接。
```

```text
用 Aptum 把这份进展改成业务负责人能据此决定是否上线的说明。
```

同一组事实面对不同接收方时，信息选择会怎么变：[examples/audience-variants.md](examples/audience-variants.md)。

## 可选：长期读者模型

无需配置即可使用。需要时可以让 Aptum 记住你确认过的稳定偏好（已知知识边界、表达偏好），存在本地，不覆盖当前任务，也不会从一次对话静默生成：

```text
使用 Aptum，根据我们的交流生成一份长期读者模型草稿，先让我确认，不要直接保存。
```
