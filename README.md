# Aptum

**适其人，适其事，适其言。**

Version: `0.0.3`

Aptum 让 AI 知道，对眼前这个人、这件事，到底该说什么，以及怎么说。

同一组事实，面对业务负责人、工程师、新加入项目的人或另一个 Agent，需要保留的信息、补充的背景、术语解释程度和表达结构本来就可能不同。Aptum 让 AI 根据“谁在读、要做什么、在哪里读”做这些判断，而不是给所有内容套同一种写法。

从能力上说，Aptum 是一个面向 AI Agent 的表达判断 Skill。它不是写作模板，也不只是润色。

> **这个读者，在这个场景下，需要获得什么信息，才能正确理解或完成接下来的事情？**

把下面这句话交给支持 Skills 的 Claude Code 或 Codex，即可让它安装：

```text
请替我安装这个 Skill：
https://github.com/Zhong-Ze-Wei/aptum
```

## 为什么需要它

AI 的回答可能事实没错，却仍然没有解决问题：

- 决策者想知道能否上线，得到的却是一串实现名词；
- 工程师需要排查故障，关键条件却被“简化”掉了；
- 业务规则还藏在人脑里，回答却假装一张映射表已经存在；
- 新 Agent 只收到“继续处理”，不知道哪些已经验证、哪些不能做。

这通常不是文笔问题，而是信息选择出了问题。Aptum 不追求固定文风，也不认为越短、越简单或越完整就一定越好。它追求的是：读者拿到完成眼前任务所需的信息，同时不被无关背景和术语拖住。

只要 AI 正在把信息交给另一个人，Aptum 就可能有用，例如回答问题、解释概念、教学、项目汇报、需求与产品文档、技术方案、README、代码说明和 Agent handoff。

## 用了以后有什么不同

下面是三个可以发生在真实工作中的示例。名称和数字只用于说明问题，不对应某个具体项目。

### 1. 同一组事实，不同读者需要不同重点

一家公司的 AI 项目准确率从 91% 降到 84%。最近加入了一批版式不同的法规 PDF，OCR 错误明显增加，模型版本没有变化，项目负责人需要决定是否继续上线。

| 面向工程师 | 面向业务负责人 |
|---|---|
| 新增 PDF 的版式导致 OCR 错误率上升，后续抽取链路的输入质量下降；模型版本没有变化，目前主要问题位于上游解析阶段。下一步应按文档版式拆分错误样本，验证 OCR 修复后的端到端准确率。 | 这次准确率下降暂时不像是模型能力退化，而是新加入的一批文件没有被正确识别。继续调模型可能解决不了问题，应该先修复文件识别，再根据复测结果决定是否上线。 |

事实没有改变。工程师需要定位故障层和验证路径；业务负责人需要知道问题性质、错误动作和决策条件。这是**适其人**，不是把技术内容一律“说简单点”。

### 2. 业务没有说清楚时，不假装规则已经存在

财务希望把人员成本自动分到不同园区，但原始数据里没有“园区”字段。过去的结果来自财务人员综合部门、岗位、成本中心、实际工作地点和历史经验进行判断。

| 直接把需求当成确定规则 | Aptum 暴露真正缺失的信息 |
|---|---|
| 建立“部门 → 园区”的映射表，即可自动划分人员成本。 | 现在还不能直接写自动划分规则。历史结果虽然存在，但园区归属并不是系统中的明确字段，部分判断来自财务人员经验。应先从历史案例中还原依据：哪些能由部门稳定决定，哪些需要岗位或成本中心辅助，哪些属于人工例外。稳定部分才能自动化，其余情况需要保留人工确认。 |

Aptum 不替业务做决定，也不会凭空发明规则。它在表达中把隐藏知识和未决条件显露出来，避免一个流畅答案掩盖问题尚未定义。这是**适其事**。

### 3. 汇报给人，还是交给另一个 Agent

一项数据迁移已完成 92%，剩余 18,420 条记录缺少可推断的邮箱；相关测试已通过，但生产 dry-run 尚未执行，产品也没有决定如何处理异常账户，而且没有生产部署授权。

| 给人同步进展 | 交给 Agent 继续工作 |
|---|---|
| 数据迁移已完成 92%。剩余异常数据无法自动补齐邮箱，正在等待产品确认处理方案；生产验证和部署尚未进行。 | **当前状态：** 已完成 92%，剩余 18,420 条无法推断邮箱。<br><br>**已验证：** 相关测试通过。<br><br>**未执行：** 生产 dry-run。<br><br>**未授权：** 生产写入和部署。<br><br>**停止条件：** 产品未确认异常账户处理策略前，不得继续生产迁移，也不得自行生成占位邮箱。 |

对另一个 Agent 来说，“进度是多少”还不够。它还必须知道证据、未完成项、权限边界和停止条件。表达结构要为安全接续服务，这是**适其言、适其场景**。

## Aptum 改变什么

- 保留会改变理解、决定或行动的事实，减少没有信息增量的内容；
- 补足读者不知道、但作者容易默认存在的最小上下文；
- 根据当前读者和任务决定术语、解释深度、信息密度与表达形式；
- 区分事实、推断和建议，保留边界、风险与停止条件；
- 当图表确实比连续文字更容易表达关系时使用图表，简单内容不机械可视化。

> **压缩表达，不压缩思想。**\
> **简化理解成本，不简化真实问题。**

Aptum 没有固定文风。面向管理者可能更短，面向工程师可能更技术化，教学需要补恰好够用的理解台阶，面向 Agent 则需要明确状态和执行边界。如果原表达已经适合当前任务，Aptum 也可以选择不改。

一次任务中的受众和角色默认只对当前任务有效。Aptum 可以使用用户明确表达的稳定沟通偏好，但不会因为一次“写给领导”就把用户长期定义成偏好管理层表达。

### 可选的长期读者模型

Aptum 无需配置即可使用。需要长期个性化时，它可以读取一份由用户确认的本地读者模型，只记录会改变信息选择、解释深度、术语或结构的内容，例如已知知识、表达偏好和希望主动抵消的表达惯性。

长期模型不会覆盖当前任务，也不会从一次对话静默生成。用户可以让 Agent 根据已有交流生成草稿，确认后保存：

```text
使用 Aptum，根据我们的交流生成一份长期读者模型草稿，先让我确认，不要直接保存。
```

## 安装与使用

也可以手动安装：

```bash
# Claude Code
git clone https://github.com/Zhong-Ze-Wei/aptum.git ~/.claude/skills/aptum

# Codex
git clone https://github.com/Zhong-Ze-Wei/aptum.git ~/.codex/skills/aptum
```

安装后重新开始会话，让 Agent 重新发现 Skills。使用时可以直接说：

```text
全程使用 Aptum，把这份项目进展改成业务负责人能够据此决定是否上线的说明。
```

```text
使用 Aptum，把当前工作写成新 Agent 可以安全继续、但不能自行部署的 handoff。
```

Aptum 不替代事实核查、领域判断、项目约定或现有 Style Guide。它负责让正确的信息，以适合当前的人、当前的事、当前场景的方式抵达。
