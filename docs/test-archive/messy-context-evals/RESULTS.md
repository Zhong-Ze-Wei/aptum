# 脏上下文多文档测试 · 结果归档（2026-09-10）

## 方法

4 个任务目录（数据分析师 / 软件开发 / 算法 / 运营），每目录 6-8 个"脏"文档，按联网调研到的真实失败模式埋针：中间位置关键约束（lost-in-the-middle）、互相矛盾的文档（context clash）、文档中不存在的必答项（编造诱饵）、跨文件拼接前提。问题问得随意（"帮我看下…发我个结果""继续把重构收尾"）。A=无 skill / B=装 Aptum v0.1.0（先读 SKILL.md），独立 agent，工作目录=任务目录。

设计依据：Liu et al. 2023（Lost in the Middle）、NAACL 2025 多文档摘要幻觉研究（75% 幻觉率、编造细节占 80-95%）、Breunig 2025 context failures 分类。详见会话记录。

**A 组（无 skill）4/4 通过全部核心检查点**——没有一个 agent 编造数字（面对"算一下 GMV"的请求，双方都给出"口径+SQL+填空模板"而非编造结果）。这显著好于文献预期，归因：上下文规模小（每目录约 3K 字）、GLM 5.3 强基线、subagent 继承全局用户配置。

## B 的可指认增量（四个场景一致的三类）

1. **证据等级显式化**（对应审计三）：软件开发的 B 把状态分成"已确认的事实/矛盾/未知"三层；算法的 B 在发送说明里显式声明"草稿严格区分事实/推断/未知，没有补造工期、责任人和测试结果"；A 组同等信息通常是隐含的。
2. **决策/输入请求明确化**（对应审计二）：软件开发 B 的"需要你先给的两个输入"；数据 B 的"可直接转发的填空模板"贴合"发我个结果"；算法 B 的"需要您决定的"三件事。
3. **善意越界的拦截**（证据纪律的负面清单）：运营 A 在公告里自加了"不会影响您的账户正常使用"——文档依据只有"不回收重复券"，账户/信用影响无依据，在有法务红线的场景这是实质风险；运营 B 恰好识别并选择不写（"内部材料只确认不回收，没写信用影响"）。同场景 B 还区分了"改文档"与"话术实际下线"的执行差异，并补了法务终审签字环节。
4. 次要增量：数据 B 的迁移窗口 sanity check（按天看 08-14/15 断层——把"文档说的"变成"验证文档说的"）；算法 B 指出 seed 方差问题决定 0.71/0.69 哪个接近真值，应优先处理。

## 结论

- **静态脏上下文（文档齐全但脏、规模 ~3K 字）下，强模型基线已能完成矛盾消解与不编造**——aptum 的增量集中在输出侧的证据等级显式化、决策入口、越界拦截，而非读取侧。这与 v0.1.0"审计而非能力"的定位一致。
- 要测出更大差距，需要更苛刻的条件：上下文规模拉长到 lost-in-middle 有效区间（≥32K）、去掉全局配置辅助、换弱模型、或在输出端点引入更强烈的编造诱饵（如文档含部分真实数字）。
- Hard Gate 8/8 通过，零编造。

## 方法教训（复跑前必读）

1. **fixture 污染**：被测 agent 拥有写权限时会直接修改任务目录（本次 A、B 两组的运营场景都改了公告草稿和话术库）。复跑前必须恢复原始文件；长期方案是每次跑前从干净副本复制。
2. 每场景 ≥3 次采样才能下统计结论（本次单次）。
3. 判定材料 `_judge-notes.md` 存于上层目录，被测 agent 仅被告知任务目录路径——但 prompt 应显式声明"只读取任务目录内文件"（本次已做）。
