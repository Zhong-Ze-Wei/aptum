# ADR-0002：恢复理解目标，并采用有范围的小型读者档案

- 状态：Accepted
- 决策日期：2026-09-12
- 关联版本：0.1.1
- 记录性质：根据已确认的讨论和已发布实现补记，不是新增运行行为
- 部分替代：[ADR-0001](0001-core-contraction-for-strong-models.md) 中仅限交付后四项审计、只补影响动作的信息及指定最低模型型号的约定

## 问题与依据

使用反馈是：回答仍可能默认读者知道工程背景，使用连续的陌生术语，即使内容完整也不容易理解。这个反馈提出了需要修正的产品问题，但不是独立对照实验，不能据此计算模型效果提升。

核对 0.1.0 实现可见，主文件强调交付后的决策和交接审计，术语与读者知识判断主要留在参考材料中。已有本地档案还混合了通用理解需求与特定代笔场景规则，部分规则范围不够明确。由此判断：需要让“理解本身”重新成为直接交付目标，并避免场景写法影响无关解释。

现有档案已经使用本地 Markdown。增加另一个隐藏目录不会自动带来更好的适配，关键在于读取、记录范围与更新方式。这里保留实现层的观察，不发布私人档案或原始聊天。

## 决定

表达过程中判断读者是否具备接上解释的背景，补足最小的对象、作用或因果；职业、使用过的术语和作者拥有的项目知识，都不能直接等同于读者已知。理解和教学不需要附带立即执行的动作，也不规定固定讲解形式。

保留小型本地读者档案，记录有依据的理解偏好和有范围的知识信息。通用条目与代笔场景分开；当前要求和直接反馈优先。知识可以变化，解释过一次不等于已经学会。

当场适配可以自动。长期写入来自明确的记录请求，或用户自愿授权后明确表达的稳定偏好；临时受众、转述和推断不自动长期化。首次使用不生成默认画像、不要求初始化。支持查看、修改、删除、暂停记录和本次不用。

事实与推断分离、风险和权限边界、交接不变量、最小干预继续保留。取消按单一模型名称定义最低支持档位；不因此承诺所有模型表现一致。

## 考虑过但未采用的方案

| 方案 | 未采用的原因 |
| --- | --- |
| 只增加画像，不动核心目标 | 可能只是更稳定地执行旧审计方式，仍漏掉普通解释中的知识缺口 |
| 所有偏好放一个全局规则表 | 代笔声音可能影响技术解释；不同领域知识容易被错误通用化 |
| 初次使用问卷或默认人物画像 | 增加开始使用的成本，也可能在缺少真实交流时制造错误标签 |
| 每轮后台推断、扫描全部历史 | 增加成本、隐私范围和误记机会，当前没有证据说明必需 |
| 完整记忆平台、数据库或强制钩子 | 当前记录规模小；普通 Skill 也不自带跨宿主后台事件能力 |

## 代价与边界

文件方式容易查看和修正，但依赖宿主可访问文件及 Agent 遵循读取约定。它不自动跨设备同步，不保证多个 Agent 同时写入安全。没有锁或受控写入工具时，不应承诺并行自动维护。

确认门槛可能减少自动积累的速度，换取更清楚的记录依据。来源、范围和确认信息会占用少量篇幅，因此需要合并重复条目，不不断追加历史。文件保存在本地也不意味着载入后的内容不会由模型服务处理。

## 验证与复审

0.1.1 已完成格式、版本、链接、用例结构及隐私隔离检查；新增 11 个读者记忆行为用例。尚未执行这些新用例的独立模型盲测，不能宣称理解成本已被实验证明下降。

后续根据真实输出复审：读者是否少追问必要背景、能否解释正确因果，事实边界是否仍完整，场景规则是否误用，新的知识反馈是否纠正旧记录。若简单解释被反复扩写，或错误画像明显拖累回答，优先调整适用范围和读取策略，不直接增加更多记忆。

只有实际发现漏读、重复确认或并行写入问题，再分别考虑宿主入口、窄范围授权或受控写入工具。用例与评分依据见 [行为评估](../../evals/rubric.md)；确切实现见 [0.1.1 差异](https://github.com/Zhong-Ze-Wei/aptum/compare/acc383d...v0.1.1)。
