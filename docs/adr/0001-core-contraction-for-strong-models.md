# ADR-0001：面向强模型，把 Aptum 从"教模型怎么写"收缩为轻量的读者与上下文对齐层

- 状态：Accepted
- 日期：2026-09-09
- 关联版本：0.1.0

> 0.1.1 修订说明：下文保留 0.1.0 的历史决策与测试表述。0.1.1 不再限定为交付后的四项审计，也不指定最低模型型号；恢复理解成本与知识缺口的直接判断，并增加有范围的本地读者档案。事实边界、交接不变量和最小干预继续保留。新版本的验证要求见 [评估规则](../../evals/rubric.md)，旧测试不作为新版本的效果证明。

## 背景

Aptum 0.0.x 的前提是：模型需要被教会"怎么写"。因此 SKILL.md 同时承担了读者判断、交付物写法（README / ADR / 需求 / 技术方案）、术语教学、自然表达、视觉表达等多重内容，references 也以"文档知识库"的方式展开。

50 组 A/B 测试（见 aptum-dev 归档）对这个世界观给出了两面的证据：

**模型已经会写的部分，Skill 不产生增量。** 文体惯例强的场景（ADR、架构评审、事故复盘、接口文档）中，No Skill 对照组与 Aptum 组大量平手——基线自己就能对号入座且质量很高。为这些场景维护"怎么写"的规则，边际价值接近零，还占用上下文。

**Skill 真正的增量集中在模型自己拿不稳的四件事上**：

1. 只识别"读者是谁"，没有进一步问"读者拿到内容后要做什么"——测试同学真正需要的是重置状态的方法，不是 Redis 入门；
2. 最可能改变决策的信息（唯一阻塞项、breaking change、需要拍板的事）被埋没——对照组在这类"决策入口前置"场景不稳定；
3. 为了让交付物显得完整，把素材中不存在的操作性细节（接口字段、命令、日期、负责人）静默补成事实；
4. 交接（尤其给下一次 AI 会话）时丢失状态、有意差异、权限边界和停止条件。

与此同时，目标模型升级到 GLM 5.3 及以上后，"教模型怎么写"这个前提本身不再成立。

## 决策

把 Core 收缩为**交付前的静默审计**，只保留四件事：

1. **接收方的下一步**——判断接收者要理解什么、判断什么、决定什么、执行什么，只补会改变其行动的信息；身份只是弱先验；
2. **决策显著度**——最可能改变接收方决策或风险判断的信息不被漏掉；只定目标，不规定格式（不强制"永远结论先行"）；
3. **证据等级硬约束**——事实 / 推断 / 建议 / 未知不混写；通用知识可以解释和建议，但"通常如此"不能写成"本项目已确认"；操作性细节输入没给就不静默补造；
4. **交接不变量**——状态、已验证 / 未验证、有意差异、权限、停止条件不因压缩丢失。

工作方式从"方法论流程"改为"native intelligence first, Aptum audit second"：默认相信模型原生完成任务，Aptum 只在输出前检查上述风险；没有发现实质问题就不改写（no-op 是一等公民）。触发条件同步收窄：只在存在真实的信息适配问题（上下文转换成本）时介入，"正在写文档"本身不构成触发。

### 保留了什么

- 四审计对应的全部硬规则，尤其是证据纪律——它在测试中是最稳定的行为差异；
- "适其人，适其事，适其言"的定位与 no-op 原则；
- references 骨架（按需加载，而非删除）；
- Humanizer 的核心思想（症状是"没有做信息判断"而非具体词汇），但降为默认不加载的修复参考。

### 降级了什么

- 三问框架、四类读者取舍、术语原则、结构与图表判断——从 Core 移入 references 或由四审计覆盖；
- deliverables.md 从"文档模板知识库"降为"高风险遗漏提醒"（只留 ADR 复审条件、breaking change 迁移动作、handoff 停止条件、API 文档不补造 schema 等）；
- visuals.md 变为 optional，prose.md 默认不加载，foundations.md 退出运行时路径；
- examples 收缩为展示"信息选择差异"的少数例子，不再示范"长什么样"。

### 取舍依据

对每条候选 Core 规则使用同一个判据：**删掉它，GLM 5.3 及以上模型是否会稳定出现一个真实、有成本的退化？** 只是"可能更不符合某种写作审美"的规则不进 Core；"可能把未知写成事实、可能埋掉唯一阻塞项、可能漏掉禁止边界、可能让接手者重新猜状态"的规则保留。最终方向：把已成为强模型原生能力的东西还给模型，Aptum 只保留能稳定产生增量的部分。

## 后果

- **放弃对弱模型的支持**：README 明确推荐 GLM 5.3 或同等级以上，不为兼容弱模型增加规则；
- **评测协议随之改变**：rubric 增加 Evidence Hard Gate（补造操作性细节直接判负）与 decision salience 维度，并引入 A（No Skill）/ B（Core）/ C（Full）三组对照——核心问题从"Aptum 是否优于基线"变为"Core 是否已拿到大多数收益、Full 的 references 是否仍有增量"；
- 0.1.0 的快速回归（9 case Core + 6 case Full，单次采样）初步支持这个设计：Evidence Gate 16/16 通过、原"决策入口前置"类全部命中；Full 仅在 handoff 与迁移类场景有小而真实的增量（已验证 / 未验证切分、停止条件、幂等提醒），未观察到 references 拖累输出。

## 复审条件

如果目标模型能力出现显著退化，或后续 held-out 评测显示 Core 在强模型上丢失了此前 Full 才能提供的增量（决策显著度、证据纪律或交接完整性出现稳定回退），应重新评审本决定。
