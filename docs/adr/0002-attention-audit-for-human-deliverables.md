# ADR-0002：为人类交付引入注意力分配审计（复审 ADR-0001 的部分归类）

- 状态：Accepted
- 日期：2026-09-12
- 关联版本：0.2.0；复审 ADR-0001

## 背景

v0.1.0（ADR-0001）把表达风格与视觉化判断排除出 Core，依据的判据是"删掉后强模型会稳定退化吗——只是写作审美的不进 Core"。上线后的使用反馈提出两个信号：

1. **"说人话"应当场景化**：凡是交付给人的内容，就应启用表达校准思想，而不是等用户明确要求润色才介入。0.1.0 把 prose.md 设为"默认不加载"，实际结果是几乎永不加载。
2. **AI 的"太完整"是真实退化**：AI 默认把每一点同等展开，次要细节也完整铺陈，读者在均匀篇幅中找不到重心——理想行为是重要的说透、次要的提一嘴。这不是审美偏好，是信息密度决策。

复审发现 ADR-0001 存在一个归类错误：当时把"说人话"理解为"伪装人类"（口语、错别字、随意结构），并据此反对；但用户实际要的是"为人类读者分配注意力"——这属于信息选择，本来就是 Aptum 的核心地盘。反对的对象（伪装人味）和需要的能力（注意力分配）不是同一件事。ADR-0001 预设的复审条件——"评测显示 Core 丢失了 Full 才能提供的增量"——由本次用户反馈触发。

## 决策

1. **Core 从四审计扩为五审计**：新增"注意力分配（接收方是人时）"——篇幅分配反映重要性差异，次要细节提一嘴即可；并把形式检查并入该审计（多处实体交互/时序/状态迁移，图表常比文字更快；画不画由模型按内容判断，不强制）。0.1.0 把视觉化整体降级的做法得到部分修正：不恢复"画图规则"，但恢复"想到检查形式"。
2. **prose.md 的加载时机改写**：从"默认不加载、仅修复时"改为"交付给人、需要校准表达时按需读取"。
3. **版本升至 0.2.0**（Core 行为变化）。

## 保留的红线（ADR-0001 中仍然成立的部分）

- 不做禁词表：症状是诊断信号，不以词计质（依据 slop 研究的结论仍有效）；
- 不用口语化、错别字、刻意不完整伪装人类写作；
- 新审计以"审计问题"形式进入，**不是生成前的禁用清单**——防预生成自我审查的污染担忧依然真实，这是 0.1.0 架构选择中必须保留下来的部分。

## 后果

- 给人的交付默认多一道注意力检查，"决策显著度"（重要的不能漏）与"提一嘴"（不重要的不能平铺）合起来构成完整的非均匀信息分配原则；
- 写给 Agent 或接口契约的输出不受影响（第五审计仅在接收方是人时生效）；
- 需以对照测试验证增量（"过度完整 vs 提一嘴"类场景），结果进测试档案。
